# AI 模拟面试

本地运行的模拟面试程序，使用 Python 3.12+、FastAPI、SQLite/SQLAlchemy、OpenAI Python SDK 和原生 HTML/JavaScript。支持录音转写、逐题复盘、专项练习、无领导小组模拟、资料复用、历史管理和用量统计；可分别配置面试模型与语音识别服务，不需要程序账户。

## 下载与开始

当前版本 **v0.1.0**。在 [GitHub Releases](https://github.com/AkaNight/ai-interview-practice/releases) 下载 `ai-interview-practice-v0.1.0.zip`，解压到自己的目录。Windows 安装 Python 3.12 或更新版本并勾选加入 PATH，然后双击 `run.bat`；首次启动会安装依赖并打开本地页面。

发布包是源码版，需要 Python，尚未制作独立 EXE。首次安装依赖需要网络。默认离线演示，不包含密钥、个人简历、录音或面试记录；在页面自行配置 API 后即可使用真实模型与转写。升级前先停止程序，将原 `data/` 和 `.env` 保存在自己的本机目录，再更新源码；数据库升级保留已有记录。

## 用量统计与预算提醒

首页展开“用量统计与预算提醒”，查看北京时间本月的实际 HTTP 请求次数、失败和结果待确认次数、服务返回的输入/输出/总 token、累计转写分钟、已知部分费用估算以及分页请求记录。SDK 网络自动重试与结构校验重试分别计数；连接测试也记录，模型列表检查单独标识。离线演示、读取历史和命中缓存不生成请求记录。

统计从升级后的第一次启动开始，无法恢复此前的花费，也不覆盖同一账户的其他应用。未返回的 token 与未定价的请求明确显示“未知”，不会当作免费；HTTP 成功仅代表接口返回，生成内容仍可能校验失败。程序中断后未确认结果的请求保留为“结果未知”。

可设置每月请求次数、人民币预算提醒，在 80% 和达到设定值时显示提示；**仅提醒，不自动阻止调用**。按自己平台填写输入/输出每百万 token 单价或语音每分钟单价，含转发倍率，分别按服务、地址和模型保存。只对之后的请求估算，旧记录不重算。估算不区分输入缓存折扣，不包含联网工具等额外费用；失败或时长未知等费用保持未知，实际花费以平台账单为准。未计价或部分计价时额外提醒，不能据此判断账户余额。

用量及提醒设置保存在本机 SQLite。请求记录仅保存时间、用途、服务地址、模型、场次标识、状态、token、时长和当时单价，不保存请求正文、回答或密钥。删除面试不删除用量账本，避免月度统计丢失。用量验收见 `USAGE_RELEASE_ACCEPTANCE.md`。

闭环：上传 PDF/DOCX 简历 → 结构化解析 → 输入公司/岗位 → 联网研究 → 面试策略 → 单题提问 → 打字或录音回答 → 确认回答文字 → 动态追问 → 结束并生成逐题报告。

## 无领导小组讨论

在面试设置的“使用模式”选择“无领导小组讨论（AI 队友）”。总人数可选3~6人，包含用户，默认你加4位AI队友；可填写讨论主题，或按岗位生成案例。可复用已经保存的公司/岗位资料。案例、具体事件和数字均为虚构模拟，不代表公司真题或真实招聘流程；没有指定领导。

准备时生成简短案例、任务、规则和具有不同风格的固定队友。开始后，队友分别表达初始观点；你可以打字或录音，检查转写后提交发言。随后每轮由两位队友轮流回应，讨论进入收尾时请你归纳方案、依据、分歧和执行步骤。最后生成群面复盘。也可提前结束讨论。

AI 队友使用文字发言，均由当前面试模型一次批量生成，不为每位队友单独调用接口。程序固定成员ID、轮换发言成员、控制总结阶段与发言次数；引用“你的原话”必须逐字来自最近提交的发言。讨论进展是AI摘要，不将未回应当成共识。模式中的讨论过程不即时教学或打分。

发言先保存，队友回应失败可重试相同发言；成功后的重复提交不重复生成队友回应。案例、角色、逐轮发言、原始/修改转写、录音和报告保存于本机，刷新可恢复。旧数据库自动增加可空 `group_json`，不删除已有记录。

报告只评价用户实际提交的发言，不把AI队友观点算作用户表现。群面分项包括论证清晰度、回应与倾听、协作推进、分歧处理和总结能力，有证据才评分；未提交总结阶段发言不评分总结能力。分项和逐次发言评价均校验用户原文证据。统计只计算保存的发言次数，不估算AI的真实语速或发言时长。

报告下方“再练一次无领导小组（沿用案例）”保留案例与角色，创建独立新讨论，用旧报告建议作为练习方向，不重新解析简历、搜索或生成案例。历史复用入口恢复小组人数和主题；原发言保持独立。

此版本采用依次发言，尚无实时抢话、多人联机或队友语音。验收见 `GROUP_ACCEPTANCE.md`；真实模型的讨论质量未在本轮付费验证。

## 专项练习与一键复练

完成面试并生成报告后，点击“按本轮计划开始专项练习”。程序创建一场独立练习，沿用本轮已解析的简历和研究快照，采用报告中的重点、建议时长与练习内容，再用**当前面试模型**生成专项策略。原问答、报告和录音保持独立；不重新解析简历、不重新搜索、不把旧回答作为新回答。换真实服务或模型也可以从旧真实报告开启新练习；演示记录只能用于离线复练。

旧报告没有下一轮计划时，使用已保存的改进建议或通用表达练习提纲，创建本地计划，不为补计划额外调用模型。练习依据仅保留少量薄弱点和表达目标，不把整份旧报告重复发送给模型。

也可以在面试设置中选择“专项练习”，输入练习重点，并选择已有资料或重新联网。专项问题直接围绕重点展开，不强制从完整自我介绍开始。

每题回答提交后，程序一次生成**本题讲评与待用的下一题**，然后暂停。讲评包含针对当前回答的观察、连续原文证据、表达提纲和时间安排建议。点击“继续下一题”使用已生成的问题；点击“重答本题”生成一条本地新轮次，问题相同，旧回答和录音保留。这两种推进操作本身不调用模型；重答提交后生成新讲评、结束时生成总报告仍会调用当前 API。接口失败或结构不合法时按既有规则有限重试。

阅读讲评的暂停时间不计入专项练习时长；暂停、讲评、待用问题和重答记录均可刷新恢复。讲评失败时已提交回答保留，可重试；讲评成功后的重复提交不重复调用模型。最后一题同样先讲评，用户再结束生成报告。达到时长或回答轮数上限后不允许继续重答，可生成报告后开启下一轮。

模拟模式保持结束后统一复盘，过程中不讲评。训练报告仅评价本场实际回答，不因为未覆盖完整综合面试而扣分。专项练习验收见 `TRAINING_ACCEPTANCE.md`。

## 本地准备资料库

每次联网研究完成后，程序自动将公司/岗位资料、面试流程、常见问题、技术/行为考察主题、有资料支持的招聘偏好、未确认的信息和来源链接独立保存在 SQLite 的 `interview_preparations` 表中。公司偏好仅表示资料中的考察重点；面经属于个案，不推测某位面试官的私人喜好。保存发生在策略生成之前，策略失败也不会丢失研究资料。

在“面试设置”展开“准备资料库”，选择以前的准备，会恢复公司、岗位、面试类型、目标时长和补充说明。原场次及已解析简历仍存在时，可勾选沿用上次简历；也可以选择新文件。勾选“使用这份资料，跳过联网搜索”会将资料复制到**新场次**，再按当前简历生成新的面试策略，不继承旧问答或旧策略。历史列表也提供“复用设置和资料”入口。复用旧简历的解析结果和旧研究不会重复调用相应 API，生成策略、提问与报告仍使用当前面试模型。

真实联网资料可跨服务/模型复用，原来的面试记录仍固定原配置。公司、岗位或面试类型改变时，不允许复用不匹配的研究资料。演示资料与真实联网资料分别显示，不把演示内容用于真实面试。

资料显示研究日期和来源，选择旧资料不会冒充重新核实。取消勾选复用或选择“新准备（重新联网）”，会重新研究并保存新版本。首次升级自动导入旧场次中已保存的研究；旧记录没有研究时间戳时明确显示“研究日期未记录”，不补造日期。

删除面试场次会清理该场资料快照，资料库的独立副本保留，便于继续复用。资料库中可单独删除某份准备及保存的设置，现有面试快照保留；已删除资料不会在重启时被再次自动导入。若原场次已删除，资料仍可复用，但可能需要重新提供简历。资料库的“设置”仅指面试参数，不保存或切换 API 密钥。

## 复盘和历史管理

结束面试后，报告包含总体评价、分项参考、逐题复盘、有原文证据的知识薄弱点和复习建议，以及可一键进入的下一轮练习计划（重点、建议时长、具体练习内容）。每题分析优点、具体问题、容易被追问的表述、作答提纲和推荐时长；逐题观察与知识薄弱点必须逐字引用最终提交的回答，程序会校验题号覆盖和原文引用。没有已作答追问时不评分追问应对。建议不编造经历或成果；未作答的题目不评价。离线演示仅展示保存结果，不提供 AI 质量评价。

口语统计在本机计算，使用**原始转写**和录音时长，包含总时长、平均时长、最长/最短回答、每题长度、疑似口头词数量及每分钟次数、疑似连续重复字和转写单位/分钟。一个汉字或一个英文/数字词算一个转写单位。修改后提交的文字单独保留，不用于计算口头词。仅纳入已提交回答；纯文字回答不计算口语指标，未知时长不参与时间和每分钟汇总。识别服务可能省略口头词，连接词也可能是正常表达，指标仅供自查；没有分析音量、语调、情绪或真实停顿。

首页点击“历史面试”，按创建时间查看记录，可继续未结束的面试、查看问答/录音/报告，或删除某场。查看历史不调用 AI，也不要求切回原模型；继续面试和生成旧场次详细报告需要原模型配置。列表每页20条。

旧版报告可直接阅读，并显示可计算的口语统计；点击“补充详细复盘”才调用原面试 API，可能产生费用。成功后替换旧报告；失败保留旧报告。已生成详细报告的重复请求返回缓存。

删除前会显示场次与确认提示。确认后清理该场所有录音（包含重录和失败尝试）、问答、报告、资料快照与策略；最后一场使用的简历原件和解析缓存也一起删除，共用简历则保留。准备资料库的独立副本可单独删除，API 设置不受影响。删除无法恢复；文件被占用时记录保留并提示重试，部分文件可能已清理。这是应用层删除，不承诺存储介质安全擦除。

## 语音回答

展开“语音转写设置（与面试模型分开）”，硅基流动默认配置为：

```text
API Base URL: https://api.siliconflow.cn/v1
模型: Qwen/Qwen3-ASR-1.7B
```

填入自己的硅基流动 Key 并保存，或选择其他兼容 `/audio/transcriptions` 的接口。“测试语音连接”仅检查密钥和模型列表；真正的识别效果需要录音验证。下载者需要自行填写自己的 Key。

面试开始后：点击“开始录音” → 浏览器允许麦克风 → 回答 → 点击“结束录音并转写” → 检查下方文字，修正专业术语 → 点击“提交回答”。录音转写不会自动提交。文字回答仍可直接使用。

建议使用新版 Edge/Chrome 打开 `http://127.0.0.1:8000`。当前录音使用 MediaRecorder，优先 WebM/Opus；不需要额外安装音频转换软件。每段至少 0.3 秒、最多 30 分钟且不超过 25 MB。录音中禁用换题、提交和修改设置，避免回答对应错题；结束时释放麦克风。

每题原始录音先保存至本机，再调用语音 API。失败时可重试已保存的录音，也可以重新录制或打字。刷新后可恢复已保存的原始转写和播放录音；确认提交后分别保存原始转写、最终回答、录音时长和识别模型。相同录音标识重试不重复保存或重新调用已成功的转写。

语音设置与面试配置完全分开，Key 保存在 `data/voice_settings.json`，不会回显给前端或进入 Git。切换语音服务不替换当前面试模型。升级启动时自动给旧 SQLite 表增加可空字段，保留原有文字面试记录。

原始转写不经过润色或填充词清理；ASR 本身仍可能漏字或改写，需人工确认。报告提供转写统计，尚未进行声学分析。

## Windows 启动

双击项目根目录下的 `run.bat`，程序启动后会自动打开 <http://127.0.0.1:8000>。关闭终端窗口或按 Ctrl+C 停止服务。

在其他电脑首次使用时，先安装 Python 3.12 或更新版本并加入 PATH，再双击 `run.bat`。它会创建虚拟环境、安装依赖，并在不存在 `.env` 时复制 `.env.example`。首次安装需要网络。

也可以在项目目录手动安装和启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item .env.example .env  # 仅在尚不存在 .env 时执行
.\.venv\Scripts\python.exe run.py
```

端口被占用时，先停止旧服务，或运行 `run.bat --port 8001`。不自动打开浏览器时可加 `--no-browser`。服务只监听 `127.0.0.1`，使用一个进程；不要以多 worker 方式运行。

## 本机 API 设置

展开首页的“API 设置（保存在本机）”，选择服务，填写 API Base URL、模型名称和 API Key，然后保存。立即生效，不需要编辑代码或重启服务。“测试连接”验证模型列表与简短文字请求，可能产生少量费用；不等于已经验证文件输入、联网或完整面试。

| 服务 | 地址/接口 | 简历处理 | 联网研究 |
| --- | --- | --- | --- |
| OpenAI 官方 | `https://api.openai.com/v1`，Responses | 文件输入 | 内置 `web_search` |
| DeepSeek 官方 | `https://api.deepseek.com`，Chat Completions | 本地提取文字后交给模型 | DDGS 独立搜索后交给模型整理 |
| 其他兼容接口/转发服务 | 用户填写，选择 Chat Completions 或 Responses | 取决于接口类型与实际支持 | Chat 使用独立搜索；Responses 要求实际支持内置搜索 |
| 离线演示 | 无 API | 简单文字提取 | 不联网 |

Chat 模式的独立搜索使用搜索结果标题、URL 和摘要，不读取网页全文；限制会保存在研究资料中。搜索失败会明确报错，不拿模型记忆冒充联网结果。

密钥仅保存在后端的 `data/api_settings.json`，不回显、不返回给前端、不写入浏览器存储，且 `data/` 已被 Git 排除。留空保留**该服务**原有密钥；勾选删除密钥并保存可移除。更换兼容接口地址时必须重新填写密钥，避免误发到另一个服务。不同厂商的密钥分别保存。

保存新配置后应开始新面试；原场次固定服务、地址、模型和接口类型，恢复原配置后可以继续。更换密钥但保持同一配置可以继续原场次。

全新下载默认没有任何密钥，使用演示模式；已有本机私有设置不属于发布源码。

## 环境变量配置（可选）

`.env.example` 默认为 `AI_MODE=demo`，页面会清楚标注“离线演示”。此模式只验证上传、文本提取、按回答选择追问、保存和报告流程：**不联网、不调用 AI、不提供真实评分，也不能用于判断 AI 面试质量**。它不是 API 出错时的自动替代方案。本机已有 GUI 保存的设置时，以 GUI 配置为准。

要运行真实面试，在本机编辑 `.env`：

```dotenv
AI_MODE=openai
OPENAI_API_KEY=你的API密钥
MAIN_MODEL=gpt-4.1
API_TIMEOUT_SECONDS=90
DATA_DIR=data
MAX_UPLOAD_MB=10
```

仅在没有 `data/api_settings.json` 时，环境变量作为初始配置；修改后重启服务，并开始新面试。`MAIN_MODEL` 统一配置。OpenAI/Responses 模式需要模型与接口支持文件输入、Structured Outputs 和 `web_search`；Chat 模式需要 JSON Output。密钥只由后端读取，不发送到浏览器，不应提交到版本管理。环境变量也支持 `AI_MODE=deepseek`、`DEEPSEEK_API_KEY`、`API_BASE_URL` 和 `API_FORMAT`（`auto`/`chat`/`responses`）。

真实模式会将简历内容和文字回答发送至所选服务；第三方转发接口也会经过转发商。联网研究只发送公司、岗位、面试类型，不向搜索步骤提供简历或密钥。API 调用可能产生费用，取决于账户、模型和工具使用。Responses 请求设置 `store=False`；这不等于对供应商其他数据保留策略的承诺。

本机已验证用户提供的 GPT 转发接口能进行文字请求、PDF/DOCX 文件输入和内置联网搜索。该转发接口的语音检查返回 503，因此语音单独使用硅基流动的千问 ASR。验收记录见 `PHASE1_ACCEPTANCE.md` 和 `PHASE2_ACCEPTANCE.md`。

## 手动验收

1. 使用 `examples/sample_resume.docx`。它是按需求案例制作的虚构样本，包含网络空间安全博士、加密流量分析、Suricata/PCAP/IAT 和无实习。
2. 公司填“中国银行”，岗位填“信息科技岗”，类型选“半结构化面试”。点击准备并开始。
3. 输入“我负责 PCAP 分析，使用 Suricata 规则检测加密流量。”，提交后应得到围绕这次回答的追问。
4. 在另一场面试输入“我们主要使用包长和 IAT 特征。”，观察追问是否变化。
5. 回答几轮，刷新页面，应恢复同一场面试。点击结束面试，看到逐题报告。用历史列表重新打开这场，检查录音和报告；删除测试场次后应无法再打开。
6. 如需真实接口验收，必须先取得用户对本轮付费测试的明确授权，再决定最小验证范围。`scripts/live_smoke.py`、`scripts/report_live_smoke.py` 和 `scripts/voice_browser_smoke.cjs` 默认拒绝运行，显式加 `--allow-paid` 才会继续；不得自行添加开关。日常开发使用本地与模拟接口测试。

## 保存与恢复

数据保存在 `data/`（可通过 `DATA_DIR` 修改）：

```text
data/
  resumes/<随机ID>.pdf 或 .docx
  interviews.sqlite3
  api_settings.json  # 本机私有密钥和配置，Git 排除
  voice_settings.json  # 独立语音服务配置，Git 排除
  interviews/<场次ID>/audio/<题号和录音ID>.webm
```

数据库包含 `Resume`、`InterviewSession`、`InterviewTurn`、`InterviewReport` 和独立的 `InterviewPreparation`，保存解析结果、研究资料及来源、策略、状态、逐轮问答和报告。浏览器只记住当前场次 ID；页面 URL 也包含 `?session=...`，可保留该地址以恢复同一场面试。换电脑不自动同步。

回答在生成下一题前单独提交保存。下一题生成失败时，页面显示“回答已保存，重试生成下一题”；重试相同题号和文本不会重复保存或重复出题。报告生成失败后面试仍标记为已结束，可以重试生成报告。研究完成但策略失败时重用已保存的研究资料。

如果服务在切换题目时中断，重新打开当前场次可恢复。已经保存的回答不允许覆盖。结束按钮不会默默丢弃输入框中尚未提交的草稿。不同 `AI_MODE` 的记录不允许混用同一场面试。

## 面试逻辑

- 不预生成题库；每轮传入简历、研究、策略、完整已保存对话、最新回答和状态。
- 模拟过程中不即时教学或评分；简短的决策标签只保存在后端。
- 同话题最多连续追问到深度 3，之后必须换话题或结束；重复问题和错误深度会被拒绝。
- 目标时长的 90% 提醒模型准备收尾，110% 时由程序强制结束；另外按时长限制回答轮数。20 分钟默认最多 12 次回答，包含追问。
- 超时条件在提交回答时检查。打字或空闲也计入场次时长，不会后台自动终止。
- 模型结构化结果不合法时重试一次；API 和网络失败返回可理解的错误，保留已保存数据。
- 报告含总体评价、分项参考、逐题原文证据、表达提纲和优先练习建议；没有回答时不打分、不生成逐题评价。

## 测试

用户要求严格节省测试费用：默认不调用真实模型、搜索、文件解析或语音 API，不自动运行完整真实面试链路，也不因修改报告而反复付费生成。只有用户明确要求或授权本轮付费验收时才执行；先说明必要的模型、调用范围和预算，再做最少次数的验证。此前提供密钥或授权过的真实测试不代表之后无限授权。用户正常在页面使用面试功能不受这些开发测试开关影响，不自动更换其模型配置。

## 项目组织

`app/api/` 处理路由，`app/services/` 集中处理 AI 和面试逻辑，`app/prompts/` 单独维护提示词，`app/models.py` 与 `app/schemas.py` 管理数据库和结构化输出，`app/static/` 提供最基础的操作页面。

创建面试时可额外传入 `preparation_id`，使用匹配公司/岗位/类型的资料库副本。省略或传 `null` 则重新研究。资料库验收见 `PREPARATION_ACCEPTANCE.md`。

创建场次默认 `mode=simulation`；专项练习使用 `mode=training` 并填写 `training_focus`。练习配置存于场次状态，旧记录默认模拟模式；升级自动为问答表增加可空 `feedback_json`，不重置既有数据。

小组讨论使用 `mode=group`，可传入 `group_size`（3~6，包含本人）和 `group_topic`（可选）。沿用 `/prepare`、`/start`、`/turn`、`/finish` 和录音接口，读取时返回 `group_scenario`、逐轮 `group_round` 与收尾记录。

仅支持 PDF/DOCX；旧 DOC 请先转存为 DOCX。支持文件输入的 Responses 模式可处理扫描 PDF；DeepSeek、Chat 兼容模式和离线演示需要可提取的文字。

尚未加入 AI 朗读、队友语音、实时抢话、准备进度显示、UI 美化或独立 EXE；不做实时双向语音对话或声学分析。

实现对照的官方资料：[文件输入](https://developers.openai.com/api/docs/guides/file-inputs)、[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、[联网搜索](https://developers.openai.com/api/docs/guides/tools-web-search)。研究使用必选 `web_search`，将实际返回的引用来源保存，再整理为结构化研究数据。

DeepSeek 的 [Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/) 明确文件输入不支持、内置搜索工具被忽略，因此本程序对 DeepSeek 使用文字解析和独立搜索。语音独立调用硅基流动，面试模型不必具备音频输入能力。

硅基流动资料：[音频转写接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)、[模型列表](https://docs.siliconflow.cn/docs/api/models-get)、[价格页面](https://www.siliconflow.cn/pricing)。历史验收已验证 `Qwen/Qwen3-ASR-1.7B` 的模型列表和中文 WAV 转写；可用模型与价格请以自己的平台为准，不随源码提供固定计费价格。
